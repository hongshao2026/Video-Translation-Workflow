# 事件驱动执行与模型调用边界

版本：1。模型负责语义判断和内容生产，本地执行器负责进程、等待、有限恢复和机械验证。正常运行期间，模型仅为查询进度而发起的调用目标为 0。

## 1. 强制调度规则

- 长时间机器任务通过 `scripts/workflow_runtime.py start` 提交。执行器持有子进程并连续完成计划中的机器步骤；不得给模型保留用来轮询媒体任务的 PTY/session ID。
- `running`、进度百分比、文件增长和正常重试只更新本地状态，不发送模型消息。仅在 `needs_agent`、`needs_user`、`failed`、`uncertain`、`completed` 时产生持久化事件。
- 主控提交后处理其他确有必要的独立工作；没有其他工作时结束当前响应，等待完成事件。不得为了表现“仍在工作”调用 `write_stdin`、`wait`、`list_agents`、反复 `Get-Content`/`tail`/查进程/GPU/时间，或循环发送“继续”。
- 用户主动问进度时允许一次状态快照；停止、取消和真实故障处理不属于进度轮询。没有新事件、用户问题或新故障证据，不得再次查询同一任务。
- 子 Agent T/A/B 按自身批次持续工作并落盘，通过宿主完成事件交接；主控不得定时询问完成度。一个 Agent 的批次进度不是重建 Agent 的理由。
- 禁止用定时唤醒模型检查“状态是否变化”代替本地事件通知。明确要求定时或额度恢复自动任务时，仍须创建并核验真实任务；其通知遵守只报告有意义变化的要求。

## 2. 哪些步骤调用模型

| 区间 | 本地执行 | 模型职责 |
|---|---|---|
| 下载 | 探测、规则选型、下载、合并、严格解码、哈希 | 规则无法处理的异常 |
| 广告准备 | 全片 ASR、抽帧/OCR、证据索引 | 全片广告语义与候选边界/遮盖判断，证据不足保留 |
| 正式源文 | 工作母版、分离、ASR、时间戳与槽位验证 | 低置信词、否定、专名等需要听辨和语义判断的疑点 |
| 翻译 | 输入投影、批次存储、ID/结构校验 | T 全文直译，A/B 分别独立全文审核，主控裁决 |
| 阅读稿 | 从正式字幕逐字排版、映射与完整性验证 | 章节语义与用户修改决定 |
| 全文生产 | 已授权 dry-run、原速 TTS、重定时、渲染、机械 QA | 无法恢复的异常、独立内容与视听质检 |
| 发布包 | 章节映射、格式/尺寸/哈希验证 | 标题简介、封面设计和内容判断 |

机械通过不代表语义通过。执行器不得自造广告、翻译、授权、音色、生产或发布包门禁，也不得替用户作人工决定。

## 3. 冻结与恢复

- 主控首次接手必须完整加载强制规范和项目冻结约束；记录路径和哈希。同一 Agent 的有效上下文仍包含规范且哈希未变时，只运行本地哈希校验，不重新输出全文。
- 新 Agent、上下文丢失或压缩摘要未保留规则时重新加载职责所需的规范与冻结交接；不能仅凭“哈希一样”声称已理解未读内容。职责所需的通用规则必须完整保留。
- `workflow_lock.json` 绑定规范、冻结输入和生产政策。首次生成时记录阶段与下一门禁；后续进度由 `runtime/state.json` 或任务状态文件表达，纯阶段/进度变化不使冻结锁失效。
- 修改规范或冻结约束后重新生成锁。历史项目不批量伪造新锁/批准；下次实际续跑时验证和迁移，保留原用户授权的内容边界。
- 每个机器步骤记录命令计划哈希、输入哈希、结果及输出哈希。续跑先验证已完成步骤；只复用全部匹配的缓存，不通过重新输出大日志验证缓存。
- 付费请求中断或响应不确定时标记 `uncertain`，禁止自动重试。必须查明结果后由项目原有授权/缓存规则处理。

## 4. 模型交接包

- T 只接收冻结源文、稳定 ID、说话人/必要上下文、术语和用户决定。A/B 分别获得同一冻结源译文对照包；不得继承另一审核者意见。
- 给每个 Agent 精简职责交接，避免复制主控整个下载/排错历史。必要规则和上下文不得因节省 token 而删减。
- 使用 `scripts/build_review_packet.py` 生成确定性投影；保留稳定 ID、源文、译文（仅审核）、说话人和上下文，逐词时间戳等完整证据留在源文件。清单绑定完整文件及投影 SHA-256、条数与 ID 顺序。
- A/B 输出问题、依据、置信度和完整覆盖证明，不重写未修改的全文。主控用固定程序应用经裁决的修改、生成字幕/阅读稿并运行机械回归。

## 5. 排错与重试

- 预先声明可恢复错误、次数上限和退避。仅明确幂等的本地步骤允许自动重试；付费 TTS 默认单次，不盲目重发。
- 失败事件提供步骤、退出码、超时信息、计划/输入哈希、日志路径及哈希、尝试记录和已验证缓存。日志必须脱敏；通知不得包含凭证、原始日志或临时媒体直链。
- 同一故障无新证据时禁止再次让模型推理。同一失败任务再次执行需新的修复证据或新计划；不能把更换失败报告文件名当成新证据。
- 已知故障恢复由程序执行。涉及系统设置、重启或超出授权的操作，仍遵守原审批边界。

## 6. 执行器与通知

执行器接受版本化 JSON 计划，机器步骤使用参数数组启动命令（不使用 shell 拼接）。每步声明前置门禁、预期输出、超时和有限重试。人工/语义步骤产生事件并停止，收到绑定该事件及计划哈希的通过记录后才可继续。

```powershell
python scripts/workflow_runtime.py start --run-dir PATH_TO_RUN --plan PATH_TO_PLAN --notify-thread CURRENT_TASK_UUID
```

`start` 立即返回 job ID、状态路径和事件路径，不返回媒体进程 session ID。后台工作进程使用 `codex queue --thread ... --message ...` 把终止/关卡事件提交给原任务；只提交一次，记录返回结果。`accepted` 仅表示宿主接受消息，不代表模型已消费；消费结果由 `ack-event` 记录。不能声称尚未核验的宿主回调已接通。

无可用通知通道时可以明确选择 `--manual-events`，但必须报告“本地执行完成后等待人工恢复”，不能把它称为全自动续跑。通知不确定时保留事件，不自动重发；人工或宿主明确恢复后才能补交。

## 7. 钩子的能力边界

`scripts/install_workflow_hooks.py` 生成项目级 `PreToolUse` 和 `UserPromptSubmit` 钩子。执行器运行期间，钩子阻止常见状态探测命令和重复状态工具；用户明确问进度/取消时放行一次。拒绝记录仅写工具名、原因与输入摘要哈希，不保存原命令或凭证。

Codex 要求用户在 `/hooks` 审阅并信任当前钩子定义；安装文件不等于宿主已加载/信任。不得自行修改信任存储或使用绕过信任参数。当前宿主的 `write_stdin` 不再次触发 `PreToolUse`，部分工具也不经过钩子，因此这是防误操作护栏，并非对所有原始工具的绝对隔离。真正减少常规轮询依靠独立执行器和完成事件。若要求不可绕过的零轮询，必须由宿主限制该 Agent 的工具集合；本仓库不能假装已经改变宿主权限。

来源：[Codex Hooks](https://learn.chatgpt.com/docs/hooks)。

## 8. 验收

- 正常等待时模型进度查询数为 0；本地心跳不进入模型上下文。
- 连续机器步骤自动衔接；输出或门禁不匹配时停下。
- 成功、失败、语义/人工关卡均有唯一事件；通知重复调用不重复发送。
- 重启后已验证缓存复用；不确定付费请求保持锁定。
- 日志和状态保留本地；诊断事件简短且脱敏。
- 分阶段记录输入、缓存输入、输出与工具调用；推理 token 属于输出子项，不重复相加。不承诺未经实测的额度节省百分比。
