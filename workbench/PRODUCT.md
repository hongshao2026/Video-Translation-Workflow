# 声轨工坊产品定义

## 1. 产品目标

声轨工坊把“下载一个视频并制作中文译配版”从依赖单台电脑、多个脚本和人工记忆的做法，整理成可检查、可暂停、可恢复、可迁移的本地工作流软件。

它服务的核心任务不是一次性生成，而是长期管理一批视频项目：用户在设置中配置翻译和语音服务，在资料库中导入视频，启动冻结的工作流运行，监督阶段进度，并在必要的人工关卡做决定。软件应让用户回答四个问题：

1. 我有哪些视频项目？
2. 每个项目现在处于哪一步？
3. 如果中断或报错，哪些结果已经安全保存，下一步该做什么？
4. 换一台设备后，怎样恢复相同的软件能力和项目证据？

## 2. 产品原则

### 本地优先，而不是单机绑定

项目目录、SQLite 索引、媒体工具和 Worker 默认运行在本机。Git 保存软件，项目迁移包保存项目快照，密钥由每台设备重新绑定。这样可以迁移，但不会把正在执行的任务伪装成可热迁移的云任务。

### 设置一次，运行时冻结

Provider、模型、提示词包、术语表和工作流政策在运行开始时写入锁定快照。设置页可以修改下一次运行的默认值，但不能悄悄改变一个正在执行或已经批准的运行。

### 真实进度，不展示安慰性百分比

有真实分母时显示 `current/total`；只有检查点时显示阶段进度；供应商没有提供可量化进度时显示“不确定进度”，不能用计时器伪造百分比。

### 失败可解释、付费请求不冒险重试

本地任务从最近通过验证的检查点恢复。翻译或语音请求如果可能已被供应商受理但客户端未收到结果，进入“计费状态待核对”，不自动重发。

### 机器门禁与人工判断分工明确

结构、哈希、轨道、时长、DTS 和解码由程序检查；章节阅读稿、音色选择与最终观看由用户决定。机器通过不等于用户已经批准。

## 3. 核心用户与场景

主要用户是需要把长视频持续制作成简体中文译配版的个人创作者或小型制作团队。典型场景包括：

- 从公开视频链接建立项目并自动探测可用画面、音轨和语言；
- 从本地原片建立项目，不复制或选择复制进资料库；
- 为不同项目选择不同厂商的大模型与语音 API；
- 让 T/A/B/C 使用同一家或不同 Provider，同时保留角色独立性；
- 离开页面后让本地 Worker 继续运行，再通过任务坞查看状态；
- 在另一台设备重新安装软件、导入项目快照并重新绑定密钥；
- 对失败任务查明原因、保留已验证结果并安全恢复。

当前不是面向多人实时协作、云端托管或公开账号体系的产品。权限、组织、共享评论和服务器调度不在现阶段范围内。

## 4. 信息架构

产品采用 Zotero 式桌面资料库结构：

- 左栏：视频库筛选、任务队列、运行记录、设置入口；
- 中栏：项目列表、搜索、当前状态和阶段摘要；
- 右栏：所选项目的概览、翻译、音色、QA、历史以及八阶段生产轨；
- 底部/侧边任务坞：跨项目后台任务、准确进度、错误和恢复动作；
- 设置：翻译服务、语音服务、工作流预设、存储与迁移、高级诊断；
- 兼容制作台：旧版角色选音、一分钟试听、MiniMax 和外部配音包功能。

界面契约见 [UX-CONTRACT.md](UX-CONTRACT.md)，视觉语言见 [DESIGN.md](DESIGN.md)。

## 5. 八阶段生产轨

| 阶段 | 目的 | 关键输出/关卡 |
| --- | --- | --- |
| 01 立项与工作流锁 | 冻结 SOP、Provider、提示词和政策 | `qa/workflow_lock.json` |
| 02 下载与源文件验收 | 探测格式、语言、分辨率并取得母版 | 媒体选择报告、未经修改母版 |
| 03 广告处理、分离与转写 | 证据化删除/遮盖广告，转写并保留时轴映射 | `qa/ad_edit_gate.json` |
| 04 翻译 T | 根据冻结源文生成完整中文候选 | 稳定 ID 全覆盖候选稿 |
| 05 双审、裁决与阅读稿 | A/B 独立全文审核，C 裁决并生成章节阅读稿 | 阅读稿验证、`qa/translation_gate.json` |
| 06 角色与选音 | 核定说话人、音色和试听 | 音色锁、用户决定 |
| 07 TTS、对轴与渲染 | 原生 1.0 倍速生成语音，以画面重定时对轴 | `qa/production_gate.json`、成片 |
| 08 QA、封面与发布包 | 全片机器验收、发布文案、章节与双比例封面 | 发布包门禁与人工抽看 |

阶段定义以 [机器可读工作流](docs/workflow.definition.json) 和生产 SOP 为准；产品界面只能展示或触发这些规则，不能降低门禁。

## 6. Provider 模型

### 已提供的适配器

- `openai-compatible`：LLM，使用保守的 Chat Completions 兼容协议；
- `minimax-llm`：LLM，基于 OpenAI-compatible 适配并使用 MiniMax 默认地址；
- `openai-compatible-speech`：同步语音，使用 `/audio/speech` 风格协议；
- `minimax-speech`：MiniMax 同步语音和音色目录。

第三方厂商只有在其接口满足相应兼容契约时才能直接配置；“OpenAI-compatible”不是对所有厂商和所有能力的保证。专用协议需要新增显式适配器，不能让配置文件加载任意可执行插件。

### 翻译角色

- T：基于冻结源文、说话人、上下文和术语表生成全文候选；
- A：独立覆盖全文，检查中文表达和上下文；
- B：独立覆盖全文，检查忠实度、数字、否定、主客体和专业逻辑；
- C：只基于 T/A/B 的冻结结果执行裁决，不代替任一审核角色。

同一个配置可以绑定多个角色，也可以按角色使用不同 Provider。无论如何，运行时绑定被锁定，失败后只能等待、修复或由用户创建新运行，不能静默换厂商继续。

### 语音规则

正式中文 TTS 一律使用 Provider 原生 `speed=1.0`。生成后不得通过 `atempo`、rubberband 或其他 time-stretch 压缩/拉长有声内容；语音长度差异由视频重定时承接。用户指定的“仅录音替换”只改变 TTS 输入，不修改已批准字幕。

详细接口见 [Provider API](docs/PROVIDER_API.md)。

## 7. 数据与多设备边界

### Git 保存

- 源码、测试、文档、依赖锁；
- 工作流定义、JSON Schema、内置提示词包；
- 不含真实数据的示例或测试夹具。

### 项目迁移包保存

- `PROJECT.md`、翻译、字幕、术语、QA、门禁、授权回执和发布文本；
- 可选媒体文件；
- `transfer-manifest.json` 中的相对路径、字节数和 SHA-256。

### 每台设备重新绑定

- API Key、Cookie、系统密钥链；
- FFmpeg、FFprobe、yt-dlp 路径；
- 本地模型、GPU/CUDA/Torch 环境；
- 本机状态数据库和 Worker 身份。

当前多设备能力是冷快照迁移。同一项目同一时间只允许一个活跃 Worker；不能把同一个 SQLite 文件放在网盘上让多台设备同时写。详见 [PORTABILITY.md](docs/PORTABILITY.md)。

## 8. 状态与恢复

任务状态至少需要区分：排队、运行、暂停中、已暂停、等待 Provider、等待另一 Worker、需修复、计费状态待核对、已取消和已完成。

恢复策略：

- 本地、幂等且有已验证检查点：修复后从检查点继续；
- 明确限流或暂时不可用：保持等待，由用户或调度器决定何时继续；
- Provider 结果不确定：停止，展示请求账本标识，人工核对；
- Provider 配置被修改：拒绝继续当前运行，创建新运行；
- 应用意外退出：本地任务标记为需修复；可能计费任务标记为不确定。

## 10. 验收标准

软件发布至少需要：

- `python -m pytest` 通过；
- `npm test` 通过；
- 安装、严格诊断和启动命令在 ASCII 源码路径验证；
- 不带真实密钥的 Git 敏感文件扫描通过；
- 使用本机凭证完成至少一个 LLM 非生成探测和最小生成调用；
- 使用本机凭证完成至少一个语音非生成探测和最小生成调用，生成物保存在 Git 忽略目录；
- 真实调用失败时不输出密钥，不对不确定请求自动重试；
- README 中只报告有证据的验证结果。

项目级成片验收仍必须遵循 [完整生产工作流](docs/LOCAL_DUBBING_WORKFLOW.md) 的放行条件。
